# Lerd Oracle Edition v1.35.0-oracle.1

O Oracle XE local prepara seu volume persistente antes de iniciar. A imagem
faststart já contém os arquivos do banco; o lerd copia esses arquivos antes que
o volume os oculte, valida o conteúdo e só então publica o diretório definitivo.
Uma cópia interrompida pode ser repetida sem deixar dados parciais no banco ativo.

O `lerd link` e o `lerd init` distinguem Oracle XE local de Oracle externo. Ao
escolher Oracle externo no terminal, o assistente também pergunta se você prefere
usar o XE gerenciado pelo lerd. Projetos que já usam Redis mas ainda não escolheram
um banco recebem essa pergunta normalmente.

A escolha local grava a conexão do preset no arquivo de configuração do app,
mesmo quando ele ainda aponta para SQLite. Falhas de inicialização são informadas,
e conexões externas existentes permanecem preservadas.

No WSL, o dashboard usa `127.0.0.1:7073` para API e WebSocket ao abrir por
`lerd.localhost`. Isso evita falhas do encaminhamento de `localhost` no Windows
que deixavam a página visível, mas sem serviços ou configurações carregados.

## Diretórios Oracle já incompletos

Esta versão preserva os arquivos existentes e bloqueia a partida quando faltam
control files ou datafiles obrigatórios. Ela não mistura uma nova cópia do banco
com dados antigos nem restaura backups automaticamente. Recupere uma cópia
completa compatível ou siga o procedimento de reinstalação explícita para dados
descartáveis, conforme o [guia de diagnóstico](../debug/oracle.md).

## Atualização

Depois da publicação da release:

```bash
lerd update
lerd about
```

A versão esperada é `1.35.0-oracle.1`. O Oracle XE local também passa a ter uma
janela de desligamento de 60 segundos para concluir suas gravações.
